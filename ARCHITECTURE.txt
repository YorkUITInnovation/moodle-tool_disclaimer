DISPLAY FLOW:
  User views course
    ↓
  course_viewed event
    ↓
  eventslib.php::tool_disclaimer_course_viewed()
    ↓
  Query tool_disclaimer (context='course', published=1)
    ↓
  Check user role restrictions
    ├─ NO roles set → applies to all
    └─ Roles set → check user has role
    ↓
  Query tool_disclaimer_log for prior response
    ├─ User accepted (response=1) → skip
    └─ No response or declined → continue
    ↓
  Load JavaScript: tool_disclaimer/disclaimer_alert
    ↓
  Create Bootstrap modal
    ├─ Title: disclaimer.subject
    ├─ Body: disclaimer.message
    └─ Buttons: Yes / No / Cancel
    ↓
  Wait 2 seconds, enable buttons
    ↓
  User clicks button:
    ├─ YES → response=1, stay on page
    ├─ NO  → response=0, redirect
    └─ CANCEL → response=2, redirect
    ↓
  AJAX: tool_disclaimer_response web service
    ↓
  Insert into tool_disclaimer_log
    ↓
  Client: redirect (if configured) or continue
DELETE FLOW:
  Admin clicks Delete
    ↓
  Confirmation dialog
    ↓
  AJAX: tool_disclaimer_delete web service
    ↓
  Delete from tool_disclaimer
  Delete from tool_disclaimer_role
  Delete from tool_disclaimer_log
    ↓
  Return to list
USER RESPONSES MANAGEMENT FLOW
================================================================================
Purpose: Allow admins to search for users, view their responses to disclaimers,
         and reset responses if users mistakenly declined.
Access: Only users with tool/disclaimer:edit capability
Location: /admin/tool/disclaimer/user_responses.php
Search/Filter Flow:
  1. Admin visits user_responses.php
  2. Form displays with search/filter options:
     - User ID (exact match)
     - First Name (partial, case-insensitive)
     - Last Name (partial, case-insensitive)
     - Context (dropdown: all, course, early_alert)
     - Response Status (dropdown: all, accepted, declined)
  3. Admin enters search criteria
  4. Form validates and sanitizes input
     - User ID: PARAM_INT (numeric only)
     - Names: PARAM_TEXT (sanitized)
     - Context: PARAM_ALPHA (alphanumeric only)
     - Response: PARAM_INT (0 or 1)
  5. Query executes with parameterized SQL
     SELECT fields FROM tool_disclaimer_log dl
     JOIN user u ON u.id = dl.userid
     JOIN tool_disclaimer d ON d.id = dl.disclaimerid
     WHERE conditions
  6. Results display in sortable, paginated table
  7. Table columns:
     - User ID
     - First Name
     - Last Name
     - Email
     - Disclaimer Name
     - Context
     - Response Status (badge: green=accepted, red=declined)
     - Attempt Count
     - Response Date (formatted)
     - Actions (Reset button)
Reset Response Flow:
  1. Admin clicks "Reset" button on user response row
  2. Browser navigates to: /admin/tool/disclaimer/reset_response.php?id={logid}
  3. Page displays confirmation with details:
     - User name and email
     - Disclaimer name
     - Disclaimer context
  4. Admin clicks "Continue" to confirm
  5. Server validates:
     - confirm_sesskey() → CSRF protection
     - require_capability() → Authorization check
     - record exists → Verify log entry
  6. DELETE FROM tool_disclaimer_log WHERE id = {logid}
  7. Redirect to user_responses.php with success notification
  8. User will see disclaimer again on next trigger event
Database Queries (User Responses):
  Table: tool_disclaimer_log
    - id: Auto-increment primary key
    - disclaimerid: FK to tool_disclaimer.id
    - userid: FK to user.id
    - objectid: Context-specific ID (course_id for course context)
    - response: 0=declined, 1=accepted, 2=cancelled
    - attempt: Response attempt counter
    - timecreated: Unix timestamp of response
    - usermodified: ID of admin who modified (if reset)
  Index: disclaimerid for fast lookups
Security Measures (User Responses):
  1. Authentication:
     - require_login() on all pages
     - No guest access
  2. Authorization:
     - require_capability('tool/disclaimer:edit', $context)
     - System context only
     - Teachers/students blocked
  3. Input Validation:
     - required_param() for mandatory params
     - optional_param() with proper PARAM types
     - Type enforcement: INT, TEXT, ALPHA
  4. SQL Injection Prevention:
     - Parameterized queries (named placeholders)
     - $DB->sql_like_escape() for LIKE queries
     - No raw SQL concatenation
  5. XSS Prevention:
     - format_string() for user data
     - fullname() for user names
     - html_writer::tag() for HTML generation
     - Mustache auto-escaping
  6. CSRF Protection:
     - confirm_sesskey() on reset action
     - sesskey() in all action URLs
     - Two-step confirmation
Files and Classes (User Responses):
  user_responses.php
    - Main page for searching/viewing user responses
    - Builds dynamic SQL with filters
    - Displays user_response_table
    - Uses user_response_filter_form
  reset_response.php
    - Confirmation page for reset action
    - Verifies record exists (MUST_EXIST)
    - Validates session key
    - Deletes log entry
    - Shows success notification
  user_response_filter_form.php (classes/forms/)
    - Extends moodleform
    - Fields: userid, firstname, lastname, context, response
    - Validation: all inputs sanitized
    - Form submission handled
  user_response_table.php (classes/tables/)
    - Extends table_sql
    - Columns: userid, firstname, lastname, email, disclaimername,
              context, response, attempt, timecreated, actions
    - Sortable by default on timecreated DESC
    - Column formatters:
      * col_response() → Badge styling
      * col_timecreated() → Date formatting
      * col_actions() → Reset button template
    - Column CSS classes for alignment
  user_response_action_buttons.mustache (templates/)
    - Renders reset action button
    - Bootstrap 4/5 compatible classes
    - Responsive: icon-only on mobile, text on desktop
    - Accessibility: ARIA labels

Use Cases:
  1. User mistakenly declined disclaimer
     → Admin searches for user
     → Finds response with status "Declined"
     → Clicks Reset
     → Confirms action
     → User response deleted from log
     → User will see disclaimer on next trigger
  2. Early alert disclaimer response audit
     → Admin filters by context="early_alert"
     → Views all teacher responses
     → Can reset specific responses if needed
  3. Course disclaimer compliance check
     → Admin filters by context="course" AND response="declined"
     → Sees which users declined course disclaimers
     → Can investigate and reset if appropriate
Performance Considerations (User Responses):
  - JOIN query on 3 tables (optimized with proper indexes)
  - WHERE clause filters reduce result set before pagination
  - Pagination: 20 records per page default
  - Column sorting handled server-side
  - No N+1 queries (single SELECT fetches all needed data)
  - Sortable columns use indexed fields

PUBLICATION CONTROL
================================================================================
published field controls if active:
  published = 1  → Active
  published = 0  → Inactive
If usepublisheddate = 1:
  → Only active between publishedstart and publishedend
  → publishedstart and publishedend are Unix timestamps
If usepublisheddate = 0:
  → published field determines status (ignore dates)
CONTEXT TYPES
================================================================================
course:
  - Shown when user views a course
  - frontpageonly controls if shown on front page
early_alert:
  - Shown when early alert event triggered
  - Separate event handler
RESPONSE VALUES
================================================================================
tool_disclaimer_log.response field:
  0 = Declined / Clicked No / Clicked Cancel
  1 = Accepted / Clicked Yes
  2 = Cancelled (treated as decline, redirect triggered)
  NULL or missing = No response yet

WEB SERVICE ARCHITECTURE
================================================================================
Enabled in: db/services.php
Called via: Moodle AJAX (core/ajax module)
Services:
1. tool_disclaimer_response
   - POST: user responds to disclaimer
   - Logs response to tool_disclaimer_log
   - Parameters: disclaimerid, userid, response, objectid, attempt
   - Response: boolean
2. tool_disclaimer_get_disclaimer
   - GET: retrieve disclaimer details
   - Parameters: id (disclaimer ID)
   - Response: disclaimer object
3. tool_disclaimer_get_role
   - GET: retrieve roles for disclaimer
   - Parameters: disclaimerid
   - Response: array of roles
4. tool_disclaimer_delete
   - POST: delete disclaimer
   - Cascades to: tool_disclaimer_role, tool_disclaimer_log
   - Parameters: id
   - Response: boolean

AJAX/JAVASCRIPT FLOW
================================================================================
Page Load:
  1. Event triggers (course_viewed)
  2. eventslib.php checks if modal needed
  3. If yes: $PAGE->requires->js_call_amd('tool_disclaimer/disclaimer_alert', 'init', params)
  4. Browser loads AMD module
disclaimer_alert.js::init():
  1. Receive params (disclaimerid, userid, objectid, redirectto)
  2. Call AJAX: tool_disclaimer_get_disclaimer
  3. Create modal with result
  4. Attach button listeners
  5. When button clicked: call AJAX: tool_disclaimer_response
  6. Hide modal
  7. Redirect (if configured)
